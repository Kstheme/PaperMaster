# PaperMaster 交互阅读页面设计草案

## v0.1.2 试用反馈与下一轮目标

精读的产品目标是让读者能通过操作理解论文。核心方法要能用可探索的架构图呈现，适合几何解释的公式要能用图形表达，教学示例允许用户改动输入并观察输出，实验表格要能在网页中交互查看。

v0.1.2 按章节展示 Markdown，方法章可附样本分步演示或 Softmax 演算。

### 已确认的产品决策

1. 完整精读和引导精读都从可探索的论文架构图开始。读者可选择模块，查看设计理由、数据流和相关公式，并通过章节目录回查实验与局限。引导精读在同一套内容上增加答题与反馈。
2. 核心架构、关键公式、主结果与关键消融默认提供交互。其余可解析的图表从目录按需打开。公式演示随输入重算，实验表格展示论文报告的数值及相应实验条件。
3. 用两篇结构明显不同的真实论文验收，分别覆盖深度学习方法与几何或优化方法。验收看读者能否解释模块的设计意图、预测改变输入后的输出趋势，以及用实验对照判断结论的适用范围。
4. 模型为每篇论文描述演示的变量、取值范围、计算关系和图形含义。浏览器验证描述，并在受支持的运算范围内实时重算。超出计算范围的公式提供分步解释。[架构决策](adr/0003-declarative-paper-demonstrations.md)
5. 核心图表的交互版使用对应原页材料。只把能够确认的模块关系、数据列和实验条件结构化。遇到歧义时，保留可查看的原图或原表片段，标出未能确认的部分。这项工作覆盖核心图表，逐条结论的证据追溯留在既有范围之外。
6. 架构图和首个核心模块就绪后即可开始阅读。余下内容自动继续生成。记录从发起精读到首个核心模块可用的耗时，用于评估等待体验。
7. 在本地提取论文版面。按需把少量核心图表裁片交给当前选中的模型，并在发送前说明。连接不支持图片时，使用可确认的文字与表格数据，同时在页面保留原图或原表片段。
8. 首版支持可拖动的二维点与向量、可编辑数值、随输入更新的曲线和柱图，以及关键中间结果。运算范围包括常用算术、距离、点积、投影、小矩阵变换、归一化和 Softmax。每个演示服务于一个明确的理解目标。
9. 组件独立保存和重试。组件失败时在对应位置显示原因与可用的退路，例如原图或分步说明。完成时列出已就绪与待补齐的核心交互。
10. Markdown 默认保留模块解释、关键公式、实验对照和局限。读者可主动保存某次试算的输入、输出与观察，附上教学演示或论文报告结果的来源类别。
11. 旧记录保留历史内容。用户主动选择「生成交互版」后，使用同一论文版本创建新的精读记录。原记录和主笔记继续可用。
12. 两篇真实论文都完成导入、架构探索、可预测的公式试算、实验与消融比较及 Markdown 导出后，再设为默认体验。验收记录首个组件可读的时间，并验证组件级失败和重试。

### v0.2.0 验收

- 本机 Codex 生成了 Attention Is All You Need（arXiv 1706.03762）与 Generalized Intersection over Union（arXiv 1902.09630）的精读结果。首个架构模块分别在约 47 秒和 80 秒后就绪。这两次生成同时发起，记录值来自各自任务创建到架构就绪的间隔。
- Chrome 实际操作了两篇的模块切换、几何拖动、两组实验表比较、原图表打开、试算笔记和 Markdown 导出。注意力示例的输出随 Query 改变移动，GIoU 示例在普通 IoU 仍为零的情况下区分了预测框位置。
- 实测通过单独重试恢复了 Transformer 主结果与 GIoU 公式。自动化还覆盖图片不被模型接收时回退到文本、拦截原表行未出现的数字、引导练习及旧记录升级。

以下为早期交互页面草案。现有平台形态和模型接入范围见 [平台设计](platform-design.md)。

## 目标与状态

用户提出为精读论文设计交互页面，以多维度理解论文及仓库。页面支持学习，阅读成果继续保存为 Markdown，并为未来 autoresearch 提供可追溯研究依据。

用户倾向于可离线打开的页面，AI 问答继续在对话中。用户随后要求回退接入、先讨论：页面模板、生成脚本、示例及接入规则已撤回。本文件仅保留设计讨论，不代表已确定实现范围或已授权继续开发。

## 三个独立维度

- 阅读方式：泛读、精读、结合仓库读、多篇比较。
- 教学交互：讲解式或互动式，决定是否使用问题验证理解。
- 展示方式：对话文字或交互页面，决定内容如何探索。

点击式页面也可用于讲解式教学。点击展开、查看答案或完成浏览都不构成掌握证据。

## 页面组织

围绕当前学习目标展开内容。左侧为简短路线和当前位置，中央为当前解释及可操作图示，来源抽屉按需展示论文位置、代码版本和相关证据。小屏下按顺序折叠，避免多个狭窄栏同时显示。

页面的不同视图共享当前选中的概念或模块。例如选择某个方法模块后，切到公式、代码或实验视图，仍围绕该模块展示对应内容；缺少对应关系时明确显示未知。

### 1. 方法与设计视图

- 点击流程节点，查看输入、操作、输出、依赖、设计目的及必要前置知识。
- 区分训练与推理路径；允许切换但不假设每篇论文都有训练阶段。
- 显示作者明确说明的理由与教学推断，支持回到来源。

### 2. 样本追踪视图

- 围绕一个具体样本逐步展示原始记录、处理结果、中间表示和输出。
- 上一步/下一步同步高亮当前模块及解释。
- 样本来源标为论文真实示例或构造的教学示例。
- 形状、维度、索引、数据字段只在实际已知或教学设定明确时展示。

### 3. 公式与算法视图

- 选中符号或运算，展示含义、形状、假设和对应代码。
- 分步展开推导或小例子，配套文字替代说明。
- 只有已定义计算关系才能提供参数操作与数值更新。
- 玩具计算标为教学演示；不能用动画暗示真实模型性能随参数如何变化。

### 4. 仓库与实现视图

- 沿实际入口展示相关调用路径，关联论文模块和配置。
- 切换官方代码摘录、教学伪代码和解释；三者来源明确。
- 高亮样本如何经过函数和接口，不默认展示整个仓库树。
- 仓库版本及读取范围可查，未核实路径不伪造。

### 5. 实验与证据视图

- 选择一项结论后显示支持结果、实验条件、消融、反例及尚不能证明的内容。
- 多篇比较时保留条件差异，不把不可比较数值做统一排名。
- 缺失数据明确显示未报告，不填零。

### 6. 问题与研究视图

- 收藏不理解之处、记录用户想法、标注待核实假设。
- 每项问题绑定当前概念、论文来源或代码位置。
- 研究假设与论文结论分别展示；可记录预期机制、替代解释和反证条件。
- 互动式每次一个核心问题，保留稳定 ID 和原题修复状态；自由文本评价只有模型实际处理后才产生。

## 内容与状态衔接

页面内容从已读取的材料和阅读成果生成；关键内容使用稳定 ID 关联模块、公式、代码位置和证据。页面更新保留选中目标和用户批注。

视图切换、展开、当前位置属于浏览状态；原题、回答依据和能力验证属于学习状态；结论、来源与研究想法属于阅读成果。三者分别记录，防止以浏览进度替代掌握进度。

Markdown 继续是阅读留痕产物；网页展示和导出应来自一致的内容。页面端新增批注需要明确保存路径：若环境不支持写回，则提供下载/导出并说明如何交回对话合并。浏览器本地缓存仅表示当前浏览器保存，不宣称已更新项目文件。

AI 问答和评价需要真实模型连接或可靠的宿主回传；没有该能力时，允许复制带当前上下文的问题到对话中。静态页面上的按钮不能假装已请求 AI 或已经通过验证。

## 首版范围建议（待运行环境选择后落实）

优先实现一个完整学习闭环：选择模块 → 追踪样本 → 查看公式/代码对应 → 检查证据 → 记录疑问 → 导出笔记。

每篇论文只采用有材料支持且有助理解的视图。公式不重要的工作不强行加入参数模拟，仓库缺失时不输出虚构调用图。布局与控件可以复用，内容与讲解结构由论文决定。

先选择一篇有全文和可访问仓库的真实论文验证；若使用构造案例验证界面，必须明确为演示，不宣称已形成真实论文阅读成果。

## 验收

以下为拟议验收标准，当前没有已接入的页面实现。

1. 点击模块会展示对应解释，并能定位真实来源。
2. 公式、代码与证据切换保留同一学习对象，未知对应关系清楚可见。
3. 样本每一步的输入输出一致，教学演示与真实运行结果可区分。
4. 查看答案和点击完成不会自动标记已掌握。
5. 批注和问题能实际导出或保存，恢复后不会丢失原题。
6. 键盘可操作主要控件，窄屏可读，图示提供文本说明。
7. 已实际检查的交互、仅静态检查和未验证能力分别报告。
