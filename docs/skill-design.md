# PaperMaster Skill 设计访谈

## 已确认需求

- 将 paperMaster v1.1.md 与 paperMaster v1.2.md 转化为 skill。
- 让用户选择阅读方式，覆盖泛读、精读、结合仓库阅读。
- 阅读后留下 Markdown 文件，承载实际阅读内容，包括多篇论文比较。

## 第一轮已确认决定

- Q1：允许直接进入任一阅读方式；结束后提供下一步选择，不自动升级。结合仓库读时按需补齐必要论文知识。
- Q2：讲解式和互动式均属有效阅读。精读默认互动式，可以随时切换；用户希望用类似命令的方式区分。讲解式记录阅读内容，互动式另外验证理解，不能把已讲解等同于已掌握。
- Q3：默认中文讲解，保留核心英文术语；双语提问与英文复述由用户开启。
- Q4：笔记正文保留整理后的知识、来源和关键误区，末尾保留简短学习状态。默认不记录逐轮聊天；保留有价值的问题、用户见解及待验证想法，并明确归属。
- Q5：四个主入口为泛读、精读、结合仓库读、多篇比较。专项解惑直接响应局部问题，不要求先选模式或启动整篇路线。

## 第二轮已确认决定

- Q6：只保留一个调用入口 `/paper-master`，以自然语言参数表达阅读方式、交互方式或操作，例如 `/paper-master 精读 讲解`。不创建 `/精读`、`/讲解`、`/笔记` 等独立命令。引号仅帮助表达，不作为严格语法要求。偏好的继承规则见 Q14。
- Q7：默认在当前工作目录的 `paper-notes/` 保存；用户指定位置优先。同一篇论文持续完善一份主笔记，比较任务另建笔记并链接已有单篇笔记；不强制为比较中的每篇论文建档。重要版本差异明确记录。
- Q8：开始建档，每完成主要讲解单元保存，结束时整理。使用 `/paper-master 笔记` 表达立即整理保存和提供链接。更新前读取现有文件，保护用户批注；个人观点与原文冲突时添加说明，不直接删除。恢复时先读取已有笔记。
- Q9：默认比较用户提供的材料，可取得这些论文的正文和附录；扩充论文集合须用户提出。未指定比较角度时推荐角度供选择，关联弱时说明限制。
- Q10：结合仓库读默认静态阅读分析，可生成教学代码；用户明确要求运行后才执行相应范围，不自动扩展为完整训练。笔记区分静态分析与实际运行结果。

## 第三轮已确认决定

- Q11：仅提供整篇材料时，识别后简短询问阅读方式并给出回复示例；意图明确则直接开始；局部材料或具体问题直接专项解惑。
- Q12（已更新）：泛读默认一次完成。精读讲解式在同一轮交付本次范围的全部精读内容和完整笔记，模块间直接推进。精读互动式分步讲解并等待当前回答。仓库阅读按模块推进；多篇比较默认完整输出，过长时分段。
- Q13：开始展示本次阅读路线与覆盖范围；泛读覆盖问题、方法概览、关键证据和局限，精读深入核心机制与必要公式，仓库阅读增加关键数据流和实现对应。附录与通用工程代码按需读取。讲解完成与掌握验证分别报告；未覆盖内容记录为后续项。
- Q14：同篇恢复沿用笔记设置，同一对话中切换阅读方式保留交互偏好；新篇未指定时，精读默认互动式，其他默认讲解式。不建立跨论文全局偏好文件。
- Q15：材料不足时明确范围，继续可确认内容。摘要不能支撑完整方法精读；仓库不可访问时可讲论文层面的实现，代码对应标记未核实。必要时请求补充材料，材料缺失不能归为用户能力不足。

## 设计树与第一轮问题

1. 阅读方式关系：可直接进入的入口，还是必须依次完成的阶段？
   - 后续：切换、必要知识补齐、完成条件。
2. 教学交互：问答验证是否必须？
   - 后续：问题预算、原题恢复、未验证状态。
3. 英语训练：默认保留到什么程度？
   - 后续：语言偏好、独立评估。
4. 笔记定位：整理后的阅读成果，还是完整教学过程档案？
   - 后续：文档结构、更新时机、恢复记录与用户批注。
5. 第一版范围：多篇比较与专项解惑是否都是独立入口？
   - 后续：比较维度、材料缺失、局部问题的结束条件。

## 已实施结构

在本项目的 `paper-master/` 中编写可分发的 skill：

```text
paper-master/
  SKILL.md
  references/
    overview.md
    deep-reading.md
    repository-reading.md
    comparison.md
    interaction.md
    notes.md
```

入口负责意图识别、共用来源原则、偏好优先级和按需加载。专项解惑直接在入口定义短流程。引用文件只在相应模式使用，避免整份原 prompt 每次全部加载。最终文件拆分可按实际篇幅调整。

`/paper-master` 是期望的用户入口形式；自然语言路由由 skill 定义，宿主是否支持原生斜杠入口需在安装时核实，不通过文档声称已注册命令。

## 原 prompt 的迁移规则

- 保留：原始证据、术语一致、事实与推断区分、数值条件、图表和公式解析、研究推理、独立理解。
- 互动式保留：有限题数、稳定问题编号、必要知识修复、返回原题、基于回答压缩问题、可见进度与真实掌握验证。
- 调整：自动进入教学改为未指定时选择；强制 A 后 B 改为直接进入与按需补齐；默认强制英语训练改为可选；统一轮次格式按交互方式适配。
- 新增：四种阅读方式的独立完成标准、比较流程、Markdown 持续留痕、单入口自然语言操作。

## 阅读笔记内容约定

正文按阅读方式组织，不强制所有笔记包含全部栏目。共用信息包括标题、论文身份与版本、来源、本次范围、阅读成果、关键来源位置、用户问题与见解、待验证想法及后续阅读项。

精读补充机制、必要公式与图表、证据和设计权衡；仓库阅读记录代码版本、入口与关键调用、样本流及论文差异；比较记录共同问题、各篇贡献、条件可比性、差异与综合判断。

文末学习记录包含阅读与交互方式、当前路线、已讲解范围、已验证目标、未验证和暂缓项、材料缺失、下一步。互动式另保存稳定题号、当前原题、必要完成标准、修复状态及简短回答依据，不抄录整个对话。

用户切换到讲解式时保留尚未验证的原题，允许推进；恢复互动式时根据当前目标继续，不把切换行为算作答题通过。

## 验收场景

1. 只给整篇论文：简短选择；明确说精读讲解：直接开始。
2. 泛读：一次概览并保存笔记，结束后不自动升级。
3. 精读讲解：同一轮覆盖本次范围的所有模块并保存完整笔记，无需用户回答或输入“继续”。
4. 精读互动：知识修复后返回原题，跳过不计为掌握。
5. 直接结合仓库读：按需补论文知识，默认不运行项目。
6. 多篇比较：只在提供的论文集合内比较，标记不可比条件。
7. 专项解惑：只完成局部目标，不生成整篇学习计划。
8. 同篇继续：读取笔记，继承设置和进度，不重启整篇课程。
9. 用户修改笔记：保留批注，不通过整文件覆盖丢失内容。
10. 材料缺失：说明已读范围，不编造内容或学习进度。
