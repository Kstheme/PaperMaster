# PaperMaster 平台设计

## 已确认的目标

- 做一个围绕论文阅读与理解的平台，支持 Codex 订阅和用户提供的 API Key。
- 完整精读一次呈现本次范围的阅读内容，引导精读加入页面内练习和反馈。两种模式共享阅读内容与交互演示。
- 阅读成果应能保存为 Markdown，为后续研究复用。首版保留论文身份、版本和入口链接，不做逐条原文证据溯源。

现有 React 原型演示两种界面。本文件定义平台首版范围。历史页面草案中的原文证据定位设想以后续版本为准。

## 第一轮已确认

1. Q1：让其他研究者也能安装，采用 npm 一键安装。交付细节见 Q5。
2. Q2：首版支持 Codex 订阅与主流第三方 API Key。接入、切换及验收见 Q6、Q7 和 Q14。
3. Q3：首版导入本地 PDF 与 arXiv 链接，仓库链接可选。
4. Q4：首版覆盖现有 skill 的泛读、完整精读、引导精读、结合仓库读、多篇比较和专项解惑。使用真实主论文走完单篇流程，使用真实对照论文覆盖多篇比较。阅读成果按 Q11 的来源范围导出 Markdown。

## 第二轮已确认

1. Q5：全局 npm 安装后用 `papermaster` 启动本地服务并打开浏览器。首批验收 Windows 和 macOS。选用 Codex 订阅时按需检测 CLI 和登录。API Key 路径可独立使用。npm 包名仍待核实。
2. Q6：首版包括 Codex 订阅、OpenAI 官方 API、可配置的 OpenAI 兼容端点，以及 Claude 和 Gemini 原生 API Key。第三方兼容端点的具体验收名单待定。
3. Q7：用户可设默认模型连接，发起任务前可见当前连接。任务开始后固定该连接。失败或限额时保留已完成成果，由用户明确决定重试或切换连接。
4. Q8：使用本地论文库。存储、凭证管理和备份见 Q10。
5. Q9：一个论文条目可有多次阅读记录，共用一份主笔记。泛读、完整精读、引导精读由用户选择。专项解惑可收入主笔记，多篇比较单独保存并引用参与论文。论文版本变化时保留旧批注所属版本。

## 第三轮已确认

1. Q10：本地 Node 服务提供网页和接口。SQLite 保存论文目录、任务及答题进度。文件目录保存 PDF 副本、笔记和材料。允许指定论文库目录和备份整库。凭证由服务读取，优先系统凭证库，允许环境变量，备份不包含凭证。
2. Q11：首版只接受具有可提取正文的 PDF。确认属于扫描 PDF 时终止导入并提示换用文字版，不做 OCR，也不发模型请求。首版提供阅读与讲解，保留论文身份、版本和入口链接，不提供逐条结论的证据映射、页码跳转或原文高亮。仓库对照静态阅读公开仓库，可标文件和函数。阅读任务只发送所需材料。
3. Q12：页面刷新或关闭不取消服务上的任务。服务退出后将未完成任务标为中断，续跑复用已校验并保存的小节。停止可取消正在进行的请求。用户明确切换连接时从剩余部分继续并记录各部分使用的模型。
4. Q13：用户可以编辑并保存主笔记。AI 可以向指定位置追加，替换已有内容先展示拟改内容。重新生成阅读内容时保留用户笔记和批注。多篇比较有独立笔记。
5. Q14：真实主论文与对应仓库覆盖单篇流程，再加入真实对照论文。完整精读可在后台分小节生成，交付完整阅读内容，无须用户逐节继续。引导精读复用内容并验收答错、补讲、返回原题、刷新恢复。接入实测覆盖 Codex、OpenAI、Claude、Gemini 与兼容端点，优先 DeepSeek 和 OpenRouter。

## 接入依据

- [Codex App Server](https://learn.chatgpt.com/docs/app-server) 记录了 ChatGPT 登录和用量限制查询。本机 CLI 已报告通过 ChatGPT 登录。尚未在 PaperMaster 内实际发起推理。
- [Sign in with ChatGPT](https://developers.openai.com/siwc/token-sharing-open-source) 提供面向开源、本地运行应用的用户授权路径。付费或远程托管产品需要单独核实可用路径。
- [Claude Messages API](https://platform.claude.com/docs/en/api/messages) 与 [Gemini 内容生成 API](https://ai.google.dev/api/generate-content) 各有原生协议，需要实测并通过适配器归一到阅读任务的输出与错误。

## 首版架构与验收

- 浏览器界面沿用 React、Radix UI 和 ECharts 原型方向。用户在论文条目内选择阅读方式、操作教学演示、答题并编辑笔记。
- 本地 Node 服务负责导入、生成任务、答题反馈和恢复。任务基于本地保存的阅读记录继续，模型连接由用户选择。Codex 会话可用于继续同一连接下的对话，论文状态和答题状态归应用管理。
- 模型适配器按接入方式归一化生成、流式反馈、取消和错误。保存产生结果时所用的模型连接标识，不保存凭证明文到论文材料或学习记录。未返回用量信息时显示未知。限额与失败不触发静默切换。
- 验收覆盖 npm 安装和启动、PDF 和 arXiv 导入、扫描 PDF 拒绝、六条阅读流程、任务取消及中断恢复、换模型后状态延续、笔记编辑和导出。模型路径分别记录实测结果，尚未实测的连接不标为已验证。

Q1–Q14 已确认，用户已授权实施。首版安装与运行说明见 [README](../README.md)，本地集成测试可运行 `npm test`。

### 首版验收结果

- Windows 上从打包后的 npm 档案安装，验证了 CLI、编译后的页面资源和本地接口。Windows DPAPI 通过了加密及读回测试。
- 实际使用 ChatGPT 登录的 Codex 连接，在两篇真实 arXiv 论文和 Tensor2Tensor 仓库上完成六种阅读流程。精读生成了样本追踪与 Softmax 演算，开放题补讲保留了原题。
- 浏览器测试使用真实 arXiv 导入和模拟模型，覆盖公式显示、图表键盘操作、样本切换、笔记保存、答题和刷新恢复。API 自动化测试覆盖四种 Key 接入协议、停止、断点续跑、切换连接、扫描 PDF 拒绝和笔记冲突保护。
- 当前环境没有用于验收的第三方 API Key 或 macOS 运行环境，相关真实服务及 macOS 安装仍需验收。npm 档案已生成，可直接安装或分享。
