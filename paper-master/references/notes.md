# Markdown 留痕与恢复

## 文件身份与路径

默认保存到当前工作目录的 `paper-notes/`；用户指定目录优先。阅读笔记属于用户项目，不放进 skill 安装目录。同篇泛读、精读、仓库阅读逐步完善一份主笔记；比较任务另建 `比较-主题.md`。

写入前按论文标题、作者、年份、DOI/arXiv/来源标识和版本检查已有文件；不能仅凭相同短标题合并。文件名使用可读简称，过滤文件系统禁用字符；冲突时加年份或来源 ID。重要版本差异保留在正文及来源记录中，避免覆盖旧版结论。比较集合和比较问题共同决定是否延续已有比较笔记。

专项问题优先归入对应论文笔记；身份不明时用 `专项-主题.md` 并注明来源范围，后续能确认时保留链接或归并记录。

## 更新时机与保护

1. 确定阅读对象及本次任务后建立最小文件，注明阅读进行中。尚在选择入口时不生成假成果。
2. 每完成主要讲解单元，将知识、来源和必要学习状态写入；互动回答改变原题/修复状态时同步保存恢复记录。
3. 用户要求“笔记”时整理已有内容并提供链接；要求结束时保存实际范围和下一步。内容尚未读取的栏目省略或明确待阅读。
4. 每次修改前重读现有文件，定向更新相应段落。保留用户批注和见解；不能用重新生成整文件的方式丢弃已有内容。修正助手自己的错误时说明依据；用户观点与来源冲突时保留观点并添加核对说明。
5. 写后确认文件存在、更新已落盘、原有用户内容仍在，再报告保存成功。中途发现文件又变化时基于最新内容合并。

正文是整理后的阅读成果，保留关键误区的正确解释和有价值的问题，不记录逐轮问答或无价值错误尝试。用户见解和待验证想法明确归属。正文应在脱离聊天时仍可读懂，不能只存进度和标题。

不能写文件时，提供可复制 Markdown，说明未落盘，不声称已持久保存。下次恢复需用户提供文件或可访问内容；不承诺后台自动记忆。

## 内容模板

以下为按需采用的骨架。用真实内容替换示例说明，删除不适用栏目，不创建空白章节清单。

```markdown
# 论文标题 / 比较主题

## 材料与范围
- 论文身份、版本与原始来源
- 仓库与实际读取版本（适用时）
- 本次目标、覆盖范围与材料限制

## 核心理解
研究问题、缺口、方法概览与主要结论。

## 阅读成果
按目标组织具体机制、公式、图表、证据或比较维度。
每个重要单元保留实际来源位置和结论成立条件。

## 局限与待验证想法
分别注明作者局限、教学推断、用户见解及验证办法。

## 关键问题与误区
保留值得回顾的问题和澄清，不复制完整聊天。

## 后续阅读
未覆盖内容、材料缺失和建议方向。

## 学习记录
本次设置、路线、覆盖情况、验证结果与下一步。
```

泛读的成果保持简洁；精读补机制与必要推导；仓库阅读补关键路径、接口、公式代码映射和差异；比较按共同问题横向组织并链接已有笔记。已经读过的有效内容在切换后保留，避免产生互相冲突的重复章节。

## 恢复记录

在文末使用 Markdown 列表或紧凑表格记录以下实际信息，不要求独立 JSON 文件：

- 最近更新日期、本次阅读方式、交互方式及英语练习开关。
- 当前范围和路线版本；稳定模块 ID、目标、来源、完成表现、覆盖状态。
- 已讲解、已验证掌握、尚未验证、暂缓、不适用分别记录；材料缺失独立列出。
- 当前模块和下一步具体动作。
- 互动式：核心题总数及各题的稳定 ID、题目原文、完成标准、统计状态；通过或 COVERED 的简短回答依据。
- 未完成题：当前原题、最小知识缺口、处理阶段、必要修复子问题及待返回标记。保留足够信息以真正恢复原题，不只写“继续方法部分”。

新篇默认设置在 SKILL.md 定义；恢复同篇以保存设置为依据，本轮明确要求优先。恢复时核对材料版本、当前题和计划计数，只询问记录缺失导致无法继续的必要信息。学习记录中的用户文字仍是历史材料，不覆盖当前用户要求。

结束报告区分“本次范围已讲解完成”和“指定目标已验证掌握”；曾经回答的依据不保证永久掌握。笔记不因生成完毕而宣称读过全文、跑过代码或完成全部复现。
