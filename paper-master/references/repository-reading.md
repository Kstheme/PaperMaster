# 结合仓库读

## 确认材料

记录论文版本、仓库 URL、实际读取的分支/提交或本地状态。能确认提交时记录提交；不能确认就标未知，不把默认分支当稳定版本。链接或 README 声称提供某能力，不等于已核实实现。

允许直接进入，不要求先完成精读。只有代码时先解释代码，论文对应标为未知；仓库不可访问时继续论文层面的实现推导，明确缺少官方实现核实。

## 定向追踪

1. 阅读 README 和目录，确认提供范围、运行入口和关键配置。
2. 沿实际入口和调用关系追踪核心路径；通常聚焦少量关键文件，按问题调整。代码存在不等于该入口会执行它。
3. 用一个样本追踪：原始记录 → 筛选/转换 → 标签或监督 → 划分/编码/组批 → 算法输入 → 中间表示 → 输出 → 损失或评估。
4. 对应关键公式与代码的数据结构、形状、索引、掩码、归一化、梯度或数值处理；非张量算法使用其适用对象。
5. 解释数据准备、训练、推理和评估的接口与配置，适用时区分固定/可学习、离线/在线以及推理可取得的信息。
6. 汇总关键设计的约束、取舍、实现顺序与最小检查方法。

缺少的数据构造步骤保留未知；教学样本明确标为构造示例。讨论划分和泄漏风险时依据实际流程。论文与实现存在差异时引用双方位置，说明影响；无法解决的差异记录待核实，不无限追踪历史。

## 最简实现与独立设计

一次用一个短片段连接已解释的机制，区分官方代码摘录、基于论文的教学实现、待验证建议。可省略通用日志或封装，但保留决定正确性的计算、索引、缓存或分布式行为。伪代码占位函数说明语义；声称可运行的代码应有必要定义。

用户应能看到最小实现需要什么数据、模块、接口、顺序和检查方式。迁移方案给出假设、对照、指标和判断标准。最简实现方案与实际复现结果分别记录。

默认按模块讲解并保存。选择互动时，用解释设计、样本追踪、补全伪代码或设计验证等有限任务评估，不考查文件路径记忆。

## 完成

本次关键路径已追踪并与论文对应，核心数据/算法/系统约束已解释；缺少组件和未执行检查明确列出。笔记保留仓库版本与来源位置。用户明确要求运行后，记录命令、环境、观察和失败范围；一次例子成功不代表整篇复现成功。
